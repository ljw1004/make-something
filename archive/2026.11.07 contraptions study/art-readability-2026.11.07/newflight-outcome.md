# Flight diagram framing revision

Author production pass for the readability revision. The previous whole-setup camera reduced the whale to roughly 80×65 CSS pixels on the phone. The fixed flight diagrams now pair a larger labeled moving-assembly detail with a smaller labeled whole-setup view. This preserves the real setting while making the machine inspectable.

`newflight_render.py` uses the unchanged canonical whale model and state/pose helpers. The large camera follows the whale's vertical height while retaining its actual pitch. It displays all visible moving-assembly descendants and the actual ground-line objects; the detail crop clips their outward continuations at a visible frame. It does not invent wire endpoints or substitute a simplified machine. The whole-setup camera retains every visible anchor, line, cradle, control and screen. The nose-dip side camera and open-hatch service camera remain the existing actual-model views.

`newflight_compose.py` creates a 1200×1200 transparent fixed diagram. The approved author pilot displayed it at 300×300 CSS pixels; integration selects a 270×270 px canvas to leave space for the goal reference picture. At 270 px, the main body uses one common projection crop and scale across the entire flight sequence, capped at 198 px wide and 150.75 px high. The whole setup uses one shared crop/scale within each chapter, so the final one-metre rise remains visible relative to its ground apparatus. The setup panel occupies 109.8×99.45 px. The two applicable teaching views occupy a separate 144.9×99.45 px panel. Explicit labels distinguish the views; opaque cream panel backgrounds are intentional diagram frames rather than attempts to blend with the scene.

The layout manifest records main crop, scale, receiving bounds, setup crop/scale and optional teaching rectangle in source pixels. Integration reserves the full canvas to keep loose pieces off the panels; the main receiving rectangle is available for a separate future receiver policy. For a small chapter reference picture, use the large moving-body view/crop rather than shrinking the complete multi-view diagram.

The completed production batch contains all thirteen fixed flight states, from `whale-running-fair` through `fair-in-the-air`, built from twenty-eight camera renders. Author checks confirmed unchanged hashes for all fifteen imported model/render sources, matching output hashes, unchanged fitted transforms, body projections inside the raw camera frame, one common main crop/scale, and one whole-setup crop/scale per chapter. Native 270 px sheets were inspected for the low-flight sequence, garden preparation and final rise; the existing nose-dip and open-hatch views remain readable, and the whole-setup view shows the final one-metre rise above the ground. The common main frame is `[160, 82, 880, 626]` in source pixels, or 198×140.85 px at the selected display size. Its optional receiving rectangle is `[148, 70, 904, 650]`; these arrays use `[x, y, width, height]`.

The production sources are `newflight_render.py` and `newflight_compose.py`. No animation, model dimensions, fitted transforms, actual line routes or story operations are changed. The render pass checks that all geometry object transforms remain identical before/after its camera/visibility work. This is an author production check, not an independent final-size acceptance, a complete mechanical proof or a human usability trial.
